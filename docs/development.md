# Firmware development and upstream review

## SonarQube Cloud analysis

`main` is the default branch on GitHub and the main branch on SonarQube Cloud.
GitHub Actions performs the analysis; Automatic Analysis is disabled.
All four PlatformIO environments pin Espressif 32 to 7.1.3, the locally verified
firmware platform. This keeps CI on the same Arduino/toolchain generation rather
than silently selecting Espressif 8 and its different compiler coverage format.
Changing that pin requires a separate firmware/SDK compatibility check.
`sonar-project.properties` separates production sources from tests and imports
the Python coverage report generated by the catalogue tests. These tests render
all four catalogues and check output path restrictions.

The Python report measures the catalogue renderer only. Native firmware tests run
under ASan/UBSan with Clang coverage instrumentation. `test/host/run_coverage.py`
exports executed source/header lines through LLVM into `cpp-coverage.xml`, in
Sonar's generic coverage format. The report includes only production paths under
`src` and `include`, never mocks or generated harnesses. Each executable has its
own profile, and the report combines executions across suites.

Before native tests, CI generates the ESP32 compilation database and uses
`firmware_coverage_inventory.py` to compile every firmware translation unit with
GCC coverage notes. The matching cross-gcov lists executable lines without
running the objects. These lines start uncovered in `cpp-baseline.lcov`; host
test hits are merged afterward. This preserves untested functions in partial
files, which generic coverage imports would otherwise omit from the denominator.
The inventory is regenerated per CI run and checked against a firmware/config
fingerprint. It neither links a coverage runtime nor flashes hardware.

Existing generated harnesses use `host_coverage.mapped()` to verify that each
instrumented fragment exactly matches production source before attaching source
line markers. LLVM's physical harness line counts are mapped back to those
verified source lines; test and mock lines are discarded. Directly compiled
production files retain their original coverage. Unit tests check both paths,
reject edited/ambiguous fragments, and retain missed lines in the report.

The runner executes eight native suites and twenty integration harnesses, covering
backend queues/control ACK/fail-open recovery, NVS migration/write failures,
network fallback/recovery, GNSS boot detection/configuration/readback/Rover,
complete Auto Base/reference workflows, status and stream commands, WebSocket
upgrade/framing, NTRIP delivery, and the logged VN2000 reference. A virtual clock
advances real workflow timeouts and the full 60-sample averaging loop.
These tests do not measure uninstrumented firmware paths or
establish behavior on hardware. The Sonar way requirement of at least 80% coverage
on new code remains enabled; missing firmware coverage still counts as uncovered.

The Auto Base location reply is parsed from const input so ArduinoJson owns its
keys and strings. Mutable queue input previously left location fields pointing
into a stack buffer that expired before the conversion report used them. The
complete lifecycle harness reproduces that failure under ASan and verifies the
location fallback succeeds after the ownership fix.

## Backend agent ownership

`include/functions/backend/Backend_Agent.h` defines the public agent interface. Its
implementation is split by responsibility under `src/functions/backend/`:

| File | Responsibility |
| --- | --- |
| `Backend_Agent.cpp` | Agent startup, transport lifecycle and data queues |
| `Backend_Agent_Storage.cpp` | NVS migration, saved identity/configuration and persistence |
| `Backend_Agent_Startup.cpp` | Receiver mode restoration and startup configuration |
| `Backend_Agent_Commands.cpp` | Backend command validation, execution and results |
| `Backend_Agent_Workflows.cpp` | Auto Base, reference checks and GNSS command exchanges |
| `Backend_Agent_Gnss.cpp` | GNSS command writes, ACK/readback, Rover transition and Survey-In status |
| `Backend_Agent_Codec.cpp` | Shared Base64/URL encoding, token fingerprints and legacy license compatibility |
| `Backend_Agent_Status.cpp` | Status and health payloads |
| `Backend_Agent_Projection.cpp` | Coordinate transformation and province projections |
| `Backend_Agent_Websocket.cpp` | RFC6455 handshake, framing and TCP reconnects |

Under `include/functions/backend/`, `Backend_Agent_Internal.h`, `Backend_Agent_Codec.h` and
`Backend_Agent_Websocket.h` are implementation headers. Keep transport framing out of command handling and status formatting.
Survey-In status uses receiver readback; the removed GGA polling state must not
be reintroduced to make RTCM-only mode depend on NMEA.

## Function directory groups

Both `src/functions/` and `include/functions/` use `backend/`, `gnss/`,
`mqtt/` and `ntrip/`. Hardware and maths retain their existing directories.
Source files include headers by their full path from `include/`; no forwarding
headers or recursive include search paths are required. Host harnesses and
build instructions use the same layout.

## Firmware ownership

- `src/main.cpp`: hardware initialization, task startup and worker loops.
- `src/hardware/Network_Manager.cpp`: boot connectivity, Wi-Fi/SIM handover,
  recovery timing and transport client selection. Its MQTT-side helpers run
  with `tcpStreamMutex` held; maintenance acquires that mutex itself.
- `src/functions/gnss/Gnss_Detection.cpp`: receiver identity probes and baud scan.
- `src/functions/ntrip/ntrip_base.cpp`: source endpoints, configuration and correction uploads.
- `src/functions/ntrip/ntrip_rover.cpp`: temporary Rover sessions, GGA and datum decoding.
- `src/functions/ntrip/ntrip_common.cpp`: shared sockets, header validation and response reading.
- `src/functions/system/cmd_handler.cpp`: serial/MQTT legacy ATG command routing.

The unused `bootstrapUM980`/`bootstrapUblox` UART configuration paths were
removed. Receiver startup is owned by `Backend_Agent_Startup.cpp`; do not add
another configuration path inside NTRIP. Write-only disconnect counters were
also removed. Moved NVS, receiver detection and network handover bodies were
compared against the previous source; command bytes, saved keys, probe timing
and socket shutdown order are preserved.

## Codec and GNSS ownership cleanup

NTRIP authentication and WebSocket nonces share the Base64 encoder. Token
fingerprints, raw-command decoding, URL encoding, delay markers and legacy
license compatibility are isolated from the agent loop in the codec module.
Legacy license calculations and receiver command/ACK/readback bodies were
compared with the prior source without changing their algorithms or timing.

Workflow code owns Auto Base/reference orchestration. GNSS command exchange,
UART ownership and reply validation live with receiver operations. MQTT
routing returns early for non-legacy topics and rejected inputs; its five-second
reconnect backoff and subscription topics remain unchanged. Host checks for
codec vectors and MQTT dispatch are documented in `test/README`.

The main status builder drops from 386 to 43 lines, stream dispatch from 92 to

The port also fixes dynamic JSON key ownership in stream/service configuration:
pass `String` keys directly so ArduinoJson copies them. Passing a temporary or
local string's `c_str()` links memory that can expire before serialization.
The native sanitizer exposed this in both the previous CORS stream handler and
the upstream helper. Consequently, before/after JSON equivalence is checked for
status; stream commands use explicit expected outcomes under sanitizers.

The Unicore query extraction in `74502f6` was not adopted: it changes when the
inner receive loop stops after a complete response. Legacy bootstrap length
changes and broad command/startup decomposition were also left out of this port.

Verification: `test/host/check_status_stream.py` executes 144 status cases and
44 stream commands using the actual implementation and ArduinoJson;
`test/host/check_websocket_frames.py` covers partial/coalesced input, header
validation, the 32 KB limit, ping/close and command delivery. Both support an
optional previous firmware root. The same WebSocket checks pass before and
after extraction; all status JSON matches the pre-refactor snapshot. Existing
Auto Base, mixed GNSS stream and MQTT dispatch checks and the PlatformIO build
are the remaining regression gates. Hardware behavior has not been measured.

### Follow-up review of remaining cleanup

A second comparison against the same sonarfix tip removes formatting/comment-only
differences before reviewing incoming code. It also adopts the status early returns,
explicit Survey-In state selection, shared loop for the two stream-status objects,
and one transport connectivity snapshot per status report. All existing verification,
NVS, GNSS quality units and workflow fields remain in the report. The native status
harness compares all 144 cases against the previous firmware and retains 44 stream
command checks under ASan/UBSan.

The remaining parser cleanup separates RTCM accumulation and UBX header handling
from mixed-stream dispatch. It preserves raw RTCM forwarding, malformed-byte
reconsideration and the current ellipsoidal-height calculation. The u-blox routing
cleanup separates key remapping and packet processing without replacing the local
message-key table or the 64-entry VALSET packet limit. A deterministic comparison
of 2,000 generated VALSET/CFG-MSG packets matches the previous routed bytes exactly.
Durable regression cases cover truncated/malformed routing input, zero/maximum
RTCM payloads, malformed UBX/RTCM header recovery and oversized UBX lengths.

Do not copy the upstream u-blox table wholesale: it omits 1127 and changes the
1094/1097 keys that the independent local vectors check. Do not revert the split
VALSET builder to a single oversized packet. Other excluded changes are cosmetic
array/byte/enum conversions, restored duplicate bootstrap/codec/storage/network
implementations, older deployment defaults, and removals of local readback,
WebSocket validation, datum conversion, startup and workflow protections. These
are intentional differences, not unresolved merge conflicts.
